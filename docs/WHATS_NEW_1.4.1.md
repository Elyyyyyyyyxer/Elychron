## 一、新增功能

### 1. iCal（.ics）文件导入

- **入口**：设置 → 数据 → 导入 iCal 文件
- **做什么**：把别人的 .ics（课程表、会议邀请、系统日历导出）变成 Elychron 待办。
  **只进待办，不写系统日历**（按用户要求）
- **字段映射**：`SUMMARY`→标题、`DTSTART`+`DTEND`→**活动**、只有 `DTSTART`→**提醒**、
  只有 `DTEND`→**截止**、都没有→**备忘**；`LOCATION`→地点、`DESCRIPTION`→描述
- **去重**：按 iCal 的 `UID` 生成稳定本地 uid（`ical-<hash>`），**重复导入同一文件不会产生重复待办**
- **导入前确认**：列出识别到的条数与前 5 条标题；导入后报告"新增 N 条 / 跳过 M 条"
- 解析器 `lib/mod/ical_import.dart` 是**纯函数**，16 条单测覆盖：折叠行、`TZID`、
  UTC 的 `Z` 换本地时区、全天 `VALUE=DATE`、转义 `\,` `\;` `\n`、空文件/非 iCal 文本
- ⚠️ **踩过的坑（已修，勿改回去）**：按扩展名过滤（`allowedExtensions: ['ics']`）会被
  Android 映射成 MIME 过滤（`text/calendar`），而很多 .ics **没有登记 MIME**
  （浏览器直下、聊天转发、adb 推的）→ 文件在选择器里**根本看不见**。
  现在改成"选任意文件 + 读出来校验内容"

### 2. 分享内容可以添加到「已有待办」

- 以前分享进来只能新建待办；现在先问一句去向：
  **新建待办** / **添加到已有待办**
- 选已有待办时：按「进行中优先、截止时间近的靠前」列出（最多 15 条，每行显示类型与时间）
- 追加语义：附件往后加、描述换行追加（不覆盖），并**更新 `updatedAt`**
  —— 否则以后多端合并会把它判成旧数据

### 3. 专注时自动免打扰

- 开关：设置 → 专注时自动免打扰（**默认开**）
- 打开专注页即切系统「完全静音」，离开时**还原成原来的档位**（不是固定还原成"全部允许"）
- **没授权时**点开关直接跳系统授权页，副标题写明状态
- ⚠️ **关键设计**：免打扰是系统级状态，App 被系统杀掉时结束回调不会执行。
  所以开启前的档位会**落盘**，下次启动发现"改过却没还原"就立刻还原
  （见 `DoNotDisturb.restoreIfStale`）—— 不做这个，用户手机会被**永久静音**
- 真机验证过：专注中 `filter=4`（静音）、退出后 `filter=1`、被杀后重开自动还原

### 4. 退出登录后仍预填账号密码

- 用户的原始诉求："主动退出登录之后，依然能够预填充登录账号密码"
- 做法：登录成功时**另存一份** `mod_last_username` / `mod_last_password`，
  **退出登录不删**（上游 `removeScholar()` 删的是 `username`/`password` 两个键，我们不动它）
- 登录页打开时读回来预填；**启动时回填**一次（老用户也能用，已登录用户的凭据补记一份）
- 存的是系统密钥库（Keystore / Keychain），不是明文数据库

### 5. 登录态失效如实显示 + 一键重登

- 用户反馈："软件保持了登录状态，但实际上已经连不上了"
- 根因：`isLogan` 一旦为 true 就不会因为会话过期回落 → 界面一直显示「已登录」，什么都没提示
- 现在：刷新时检测**认证/会话类**错误（未登录 / ticket / CAS / 401 / 用户名或密码…）→
  置 `Scholar.sessionInvalid` → 设置页那一行变成
  **「登录已失效」** + 副标题「连不上学校服务器，请点右侧重新登录」+ 右侧「重新登录」，
  点整行直接打开登录页
- 判据做了**双向测试**：认证类要认出来，而"教务网超时"这种**单模块抽风不能误判**成登录失效

### 6. 一键「复制反馈信息」

- 设置 → 数据 → 复制反馈信息：**机型 / 系统版本 / App 版本 + 最近 120 行脱敏日志 + 反馈模板**
  一次进剪贴板，直接粘到 QQ 群或论坛帖
- 日志里的密码、Cookie、学号自动隐藏

### 7. 更新检查加 Gitee 兜底

- 原来只读 GitHub，国内常常连不上 → 现在按 **GitHub → Gitee** 顺序尝试，谁先回应用谁
- **「去下载」打开实际回应的那个源**，不会再"提示有新版本却打不开下载页"

## 二、修复

### 1. 闹钟关掉后一直重复弹（重要）

- **现象**（用户反馈）："后台被清掉了闹钟就不会触发，但是一打开软件，闹钟弹窗会一直触发，
  关了还会一直重复弹闹钟"
- **根因**：去重记录写在 `TaskAlarmCoordinator` 里，且写成
  `if (TaskAlarmCenter.current.value == null) _fired.clear();`
  —— 用户一点掉弹窗（`current` 变 null），下一秒 tick 就**清空记录**，
  而那条待办的提醒时刻仍在"同一分钟内" → 再弹，循环不止
- **修法**：去重改为**按「提醒时刻」**（`uid@毫秒`），并且**不再因为弹窗被关闭而清空**；
  改时间或"延迟提醒"到新时刻算新的一次；前台 tick 与通知路径共用同一套去重
- 顺带修：**排定失败被静默吞掉且永不重试** —— 原来 `syncAll` 的 `finally` 里也记签名，
  一次失败就再也不重试（症状正是"闹钟不响且查不出原因"）。现在失败不记签名（下次重试），
  并把排定结果写进诊断日志
- 8 条回归测试（含"关掉弹窗后不会再弹"这条直接对应反馈的用例）

### 2. 「接下来」的倒计时停在旧值

- 卡片上的「还有 N 分钟」原来只在页面碰巧重建时才重算，实测出现状态栏 13:16
  而卡片还写着「还有 24 分钟」（13:01 的旧值）
- 现在每 20 秒自动重算，且只在看「接下来」时刷新

### 3. 课程/考试信息弹层重做

- 原来用 iOS 风格 ActionSheet，里面有一条显示日期/地点但**内容是空白的选项**
- 换成钉钉风格弹层（大标题 + 图标信息行 + 粉色「知道了」）

### 4. 登录判据应只看统一身份认证

- 原来是「6 个子站全为 null 才算登录成功」→ **任何一个子站抽风都让人登不进来**
  （实测：教务网故障导致首次登录直接失败，而身份认证其实已通过）
- 现在身份通过即算登录成功，子站失败降级为「部分模块暂不可用」

### 5. 刷新很卡、要退出重进才能刷好（用户反馈）

- **排查过程**（逐项排除，结论写在代码注释里）：
  抓取已经是 `Future.wait` **并行**；单请求超时 8 秒；`maxRetries = 1`；
  刷新锁是文件锁 + 心跳 + 30 秒过期恢复 —— **架构都没问题**
- **真凶**：「异步刷新」**默认关闭** → 界面要等所有模块全刷完（最坏近 20 秒）才一次性更新，
  看着就像卡死；用户等不及就退出重进（重进读缓存所以"立刻就好"）
- **修法**：改为**默认开启** + 对老用户做**一次性迁移**（标记键，幂等）；
  设置里的开关保留，用户自己关掉后不会再被打开
- 迁移时踩到的坑：只改数据库不够，**界面读的是数据库打开时创建的 Rx** →
  不同步的话设置页一直显示"关着"，用户以为没生效（已补 Rx 同步）

### 6. 界面报错"一长串非常吓人"（用户点名）

- 用户原话："统一认证账号登录时如果输错了会产生很长很长的报错表"
- 根因：界面直接贴 `异常.toString()`，而 `ExceptionWithMessage` 会拼成
  `消息 + 分隔符 + 详情`（详情里是 URL、状态码、响应片段），一屏放不下
- **修法**：新增 `lib/mod/friendly_error.dart` —— **界面只给人话，细节去诊断日志**：
  砍掉详情段、只取第一行、去异常类名前缀、按关键词映射常见故障、兜底截断到 42 字
- 已接入：登录失败、导出/导入失败、复制反馈失败、AI 整理失败、选图失败

## 8.3 登录：修掉「老是显示登录已失效」的误报

- **现象**：设置页频繁显示「登录已失效」，而用户其实好好的。
- **根因**：判据太宽 —— 把**模块自己的会话**当成了用户登录失效：
  `学在浙大：未登录`、`智慧研工未登录或会话已失效` 是各子站自己的登录，
  设计上就是可容忍降级（代码里本来就有 `isDegradedRefreshText` 标记，当时没用上）；
  再加上关键词里有 `cas` / `401` 这种**短子串**，而错误详情几乎都带 URL（含 `/cas/`）。
- **修法**：只认两件事 —— ① **统一身份认证（CAS）这一路失败**；
  ② 措辞明确的凭据/会话失效。并**排除 `isDegradedRefreshText` 标记的降级**。
  关键词表里明确注释"别再加回 `cas`/`401`/`未登录`"。
- 6 条**误报回归测试**（用真实消息原文）。

## 8.4 课前提醒：算法 + 课间阈值

- **功能此前不存在**：课程同步到系统日历的事件**根本没设提醒**。
- 算法在 `lib/model/class_reminder_rule.dart`（纯函数，20 条测试）：
  - 前一节没课 → 提前 **30** 分钟（最初 20，用户后来改为 30，见 8.7）；
  - 前一节有课（连着上）→ 提前 **10** 分钟；
  - 午饭/晚饭**视作一节空课**；"前面有没有课"按**空余是否大于课间时长**判断。
- **课间阈值默认 15 分钟**（可配置）：本校真实节次表的间隔只有
  **5（小课间）/ 25（大课间）/ 60（饭点）** 三种，所以阈值取 6~25 之间任何值结果都一样。
- 饭点默认 `12:25–13:25`、`17:50–18:50`（第 5→6、第 11→12 节之间的空档）。

## 8.7 用户新提的四项（2026-09-15 已完成）

1. **文件选择分类**：附件选择处先问一句来源 ——
   **「从图库选择图片」**（`FileType.image`，系统给相册，能看缩略图）
   / **「从文件管理选择」**（不限类型，交给手机自带文件管理）。
   刻意**不加扩展名过滤**（会被映射成 MIME 过滤，出现"文件明明在却看不见"，iCal 导入踩过这个坑）。
2. **动画卡顿（闹钟页等）**：闹钟页的毛玻璃用的是 `sigma 24 / 40` 的**实时**高斯模糊，
   而原来**每秒刷新的时钟文字在模糊层内部** → 每秒重算一次大面积模糊，必然掉帧。
   修法：把「静态毛玻璃层」与「会变的内容」拆成**兄弟节点**，并给模糊层包
   `RepaintBoundary`（只光栅化一次）；装饰光斑同理。**观感不变**。
3. **课前提醒提前量**：前面没课时 **20 → 30 分钟**（连着上课仍是 10 分钟）。
### 8.7 补充：④ 的证据链

**右滑完成的真 bug**：`confirmDismiss` 正是在**手指抬起那一刻**被调用的，而原代码在里面 `await confirmCompleteTask(...)`（有未完成子待办时才弹确认框）→ 弹框刚出现就被同一个抬手事件误触关闭 → 返回 false → 什么都没发生。这正好解释了"**没有子待办的能滑、有子待办的滑不动**"。修法：不在该回调里 await，**先让卡片弹回、下一帧再走完成流程**（复用 `_toggleDone`）。

## 8.8 又一批四项（2026-09-15 第二轮）

1. **专注切休息时不关免打扰 → 已修** ✅
   - 现象（用户反馈）："切休息模式时不会自动关掉免打扰，导致无通知，我也不知道我要休息了"。
   - 原因：免打扰只在**进出专注页**时开关（进=静音、走=还原），中间的**段切换没管它**。
   - 修法：段落切换处（`focus_page.dart` 的 `_lastPhase` 比较）按当前阶段同步 ——
     工作段静音、休息段还原；`dispose` 里再兜一次（幂等）。
2. **专注期间被外部分享打断 → 已修** ✅
   - 现象："如果在专注期间通过外部分享进入 Elychron，会强行打断并提示未正常退出"。
   - 原因：分享流程会切到待办页并弹新建面板，直接压在专注页上；会话因此停在"未完成"，
     下次进专注页就提示"上次没有正常结束"。
   - 修法：`home_mod_hooks._handleShared` 里**先判断是否有未结算的专注会话**；
     是则把分享内容**攒起来**（每 3 秒看一次是否结束），专注结束后再自动弹出来处理 —— **全程不打断**。
3. **「接下来」多个进行中的项目只显示一个 → 已修** ✅
   - 现象（用户反馈）："同时有两个正在进行的项目⋯⋯只会显示一个进行中"。
   - 原因：界面只认 `items.first` 当顶层大卡；第二条进行中的条目掉进「之后还有」，
     而那一行**还故意不显示「进行中」**（`_row` 里的旧条件）→ 用户根本看不出它在进行。
   - 修法：把「顶层大卡 / 折叠的其它进行中 / 之后还有」三段划分做成**纯逻辑**
     （`model/upcoming.dart` 的 `layoutUpcoming`，13 条单测）。顶层默认**课程优先**
     （`defaultTopRunningIndex`：有 `PeriodType.classes` 就给它，否则按开始时间最早）；
     其余进行中的条目在顶层卡片下方**折叠成一叠小卡**（逐级内缩 + 「同时还有 N 个进行中 ·
     点一下置顶」），点任意一张把它换到顶层，原来那张落回折叠堆（点错了能点回来）。
     - 置顶按 `dedupeKey` 记**不按下标**：这一页每 20 秒跟着心跳重算，下标随时会变。
     - 置顶**只在那条还进行中时有效**：课程/日程的 uid 整套复用（同一门课每天同一个 uid），
       按"还在不在列表里"判断会让置顶一直留到下次开课（好几天后莫名冒到顶层）。
     - 进行中的条目**不再同时出现在「之后还有」**，避免同一条显示两遍。
   - ⚠️ 没有真机验证（用户外出、手机断连）。

4. **日程页上滑折叠日历（只留一周）→ 已做** ✅（农历那部分**没做**，见下）
   - 做法：折叠的呈现**直接用 `TableCalendar` 自带的 `CalendarFormat.month ⇄ .week`**，
     不手画一周条 —— 它自己就是 `AnimatedSize` 包着的（`formatAnimationDuration` 默认
     200ms），高度变化天然平滑；且选中态、今天、小圆点标记在周视图下全都照旧。
     手画一条「一周条」要把选中/今天/标记/横向翻周全部重写一遍，风险大得多。
   - 手势：`NotificationListener<ScrollNotification>`（`calendar_view.dart` 的日历分支）→
     `CalendarController.handleDayListScroll` → 判定在 `mod/calendar_fold.dart`
     （`CalendarFoldGesture`，13 条单测）。上滑列表 → 折成一周；**回到顶部继续下拉** → 展开整月。
   - 三个必须踩住的坑（都写进注释和单测了）：
     1. **只认竖向通知**：`TableCalendar` 内部是横向翻页的 `PageView`，它的通知同样会冒泡
        出来，而那时 `metrics.pixels` 是"第几页"的偏移 —— 拿它判断会让日历莫名折叠。
     2. **只认"手指直接带着动"的通知**（`dragDetails != null`）：折叠后列表因为日历变矮而
        **变高**、内容可能不再溢出，位置会自动弹回 0；那种自动回弹若被当成"用户下拉"，
        就会立刻展开 → **一折一展死循环**。
     3. **当天列表改成"永远可拖"**（`AlwaysScrollableScrollPhysics.applyTo(当前平台物理)`）：
        当天只有一两条时列表本来滚不动，手势就没有载体。用 `applyTo` 接在平台物理外面
        （本 App 是 CupertinoApp → `BouncingScrollPhysics`），只多出"永远可拖"，回弹手感不变。
   - ❌ **图二里的农历没做**：仓库里没有农历换算（`TimeHelper.chineseDayRelation` 只是
     "今天/明天"这种相对说法，不是农历）。要加得引一个农历库或自己塞一张换算表，
     属于独立小功能，等用户明确要了再做。**其余（星期 + 日期 + 小圆点标记）与图二一致。**
   - ⚠️ 没有真机验证（用户外出、手机断连）：折叠手感、阈值（28px）是否合适要上手才知道。
