## 一、新增功能

### 1. iCal（.ics）文件导入

- **入口**：设置 → 数据 → 导入 iCal 文件
- **做什么**：把别人的 .ics（课程表、会议邀请、系统日历导出）变成 Elychron 待办。
  **只进待办，不写系统日历**（按用户要求）
- **字段映射**：`SUMMARY`→标题、`DTSTART`+`DTEND`→**活动**、只有 `DTSTART`→**提醒**、
  只有 `DTEND`→**截止**、都没有→**备忘**；`LOCATION`→地点、`DESCRIPTION`→描述
- **去重**：按 iCal 的 `UID` 生成稳定本地 uid（`ical-<hash>`），**重复导入同一文件不会产生重复待办**
- **导入前确认**：列出识别到的条数与前 5 条标题；导入后报告"新增 N 条 / 跳过 M 条"
- 解析器 `lib/mod/ical_import.dart` 是**纯函数**，16 条单测覆盖：折叠行、`TZID`、
  UTC 的 `Z` 换本地时区、全天 `VALUE=DATE`、转义 `\,` `\;` `\n`、空文件/非 iCal 文本
- ⚠️ **踩过的坑（已修，勿改回去）**：按扩展名过滤（`allowedExtensions: ['ics']`）会被
  Android 映射成 MIME 过滤（`text/calendar`），而很多 .ics **没有登记 MIME**
  （浏览器直下、聊天转发、adb 推的）→ 文件在选择器里**根本看不见**。
  现在改成"选任意文件 + 读出来校验内容"

### 2. 分享内容可以添加到「已有待办」

- 以前分享进来只能新建待办；现在先问一句去向：
  **新建待办** / **添加到已有待办**
- 选已有待办时：按「进行中优先、截止时间近的靠前」列出（最多 15 条，每行显示类型与时间）
- 追加语义：附件往后加、描述换行追加（不覆盖），并**更新 `updatedAt`**
  —— 否则以后多端合并会把它判成旧数据

### 3. 专注时自动免打扰

- 开关：设置 → 专注时自动免打扰（**默认开**）
- 打开专注页即切系统「完全静音」，离开时**还原成原来的档位**（不是固定还原成"全部允许"）
- **没授权时**点开关直接跳系统授权页，副标题写明状态
- ⚠️ **关键设计**：免打扰是系统级状态，App 被系统杀掉时结束回调不会执行。
  所以开启前的档位会**落盘**，下次启动发现"改过却没还原"就立刻还原
  （见 `DoNotDisturb.restoreIfStale`）—— 不做这个，用户手机会被**永久静音**
- 真机验证过：专注中 `filter=4`（静音）、退出后 `filter=1`、被杀后重开自动还原

### 4. 退出登录后仍预填账号密码

- 用户的原始诉求："主动退出登录之后，依然能够预填充登录账号密码"
- 做法：登录成功时**另存一份** `mod_last_username` / `mod_last_password`，
  **退出登录不删**（上游 `removeScholar()` 删的是 `username`/`password` 两个键，我们不动它）
- 登录页打开时读回来预填；**启动时回填**一次（老用户也能用，已登录用户的凭据补记一份）
- 存的是系统密钥库（Keystore / Keychain），不是明文数据库

### 5. 登录态失效如实显示 + 一键重登

- 用户反馈："软件保持了登录状态，但实际上已经连不上了"
- 根因：`isLogan` 一旦为 true 就不会因为会话过期回落 → 界面一直显示「已登录」，什么都没提示
- 现在：刷新时检测**认证/会话类**错误（未登录 / ticket / CAS / 401 / 用户名或密码…）→
  置 `Scholar.sessionInvalid` → 设置页那一行变成
  **「登录已失效」** + 副标题「连不上学校服务器，请点右侧重新登录」+ 右侧「重新登录」，
  点整行直接打开登录页
- 判据做了**双向测试**：认证类要认出来，而"教务网超时"这种**单模块抽风不能误判**成登录失效

### 6. 一键「复制反馈信息」

- 设置 → 数据 → 复制反馈信息：**机型 / 系统版本 / App 版本 + 最近 120 行脱敏日志 + 反馈模板**
  一次进剪贴板，直接粘到 QQ 群或论坛帖
- 日志里的密码、Cookie、学号自动隐藏

### 7. 更新检查加 Gitee 兜底

- 原来只读 GitHub，国内常常连不上 → 现在按 **GitHub → Gitee** 顺序尝试，谁先回应用谁
- **「去下载」打开实际回应的那个源**，不会再"提示有新版本却打不开下载页"

## 二、修复

### 1. 闹钟关掉后一直重复弹（重要）

- **现象**（用户反馈）："后台被清掉了闹钟就不会触发，但是一打开软件，闹钟弹窗会一直触发，
  关了还会一直重复弹闹钟"
- **根因**：去重记录写在 `TaskAlarmCoordinator` 里，且写成
  `if (TaskAlarmCenter.current.value == null) _fired.clear();`
  —— 用户一点掉弹窗（`current` 变 null），下一秒 tick 就**清空记录**，
  而那条待办的提醒时刻仍在"同一分钟内" → 再弹，循环不止
- **修法**：去重改为**按「提醒时刻」**（`uid@毫秒`），并且**不再因为弹窗被关闭而清空**；
  改时间或"延迟提醒"到新时刻算新的一次；前台 tick 与通知路径共用同一套去重
- 顺带修：**排定失败被静默吞掉且永不重试** —— 原来 `syncAll` 的 `finally` 里也记签名，
  一次失败就再也不重试（症状正是"闹钟不响且查不出原因"）。现在失败不记签名（下次重试），
  并把排定结果写进诊断日志
- 8 条回归测试（含"关掉弹窗后不会再弹"这条直接对应反馈的用例）

### 2. 「接下来」的倒计时停在旧值

- 卡片上的「还有 N 分钟」原来只在页面碰巧重建时才重算，实测出现状态栏 13:16
  而卡片还写着「还有 24 分钟」（13:01 的旧值）
- 现在每 20 秒自动重算，且只在看「接下来」时刷新

### 3. 课程/考试信息弹层重做

- 原来用 iOS 风格 ActionSheet，里面有一条显示日期/地点但**内容是空白的选项**
- 换成钉钉风格弹层（大标题 + 图标信息行 + 粉色「知道了」）

### 4. 登录判据应只看统一身份认证

- 原来是「6 个子站全为 null 才算登录成功」→ **任何一个子站抽风都让人登不进来**
  （实测：教务网故障导致首次登录直接失败，而身份认证其实已通过）
- 现在身份通过即算登录成功，子站失败降级为「部分模块暂不可用」

### 5. 刷新很卡、要退出重进才能刷好（用户反馈）

- **排查过程**（逐项排除，结论写在代码注释里）：
  抓取已经是 `Future.wait` **并行**；单请求超时 8 秒；`maxRetries = 1`；
  刷新锁是文件锁 + 心跳 + 30 秒过期恢复 —— **架构都没问题**
- **真凶**：「异步刷新」**默认关闭** → 界面要等所有模块全刷完（最坏近 20 秒）才一次性更新，
  看着就像卡死；用户等不及就退出重进（重进读缓存所以"立刻就好"）
- **修法**：改为**默认开启** + 对老用户做**一次性迁移**（标记键，幂等）；
  设置里的开关保留，用户自己关掉后不会再被打开
- 迁移时踩到的坑：只改数据库不够，**界面读的是数据库打开时创建的 Rx** →
  不同步的话设置页一直显示"关着"，用户以为没生效（已补 Rx 同步）

### 6. 界面报错"一长串非常吓人"（用户点名）

- 用户原话："统一认证账号登录时如果输错了会产生很长很长的报错表"
- 根因：界面直接贴 `异常.toString()`，而 `ExceptionWithMessage` 会拼成
  `消息 + 分隔符 + 详情`（详情里是 URL、状态码、响应片段），一屏放不下
- **修法**：新增 `lib/mod/friendly_error.dart` —— **界面只给人话，细节去诊断日志**：
  砍掉详情段、只取第一行、去异常类名前缀、按关键词映射常见故障、兜底截断到 42 字
- 已接入：登录失败、导出/导入失败、复制反馈失败、AI 整理失败、选图失败

  现在用 getter，将来加设置项只需接 UI + 持久化，**调用点一行都不用改**

     不手画一周条 —— 它自己就是 `AnimatedSize` 包着的（`formatAnimationDuration` 默认

     手画一条「一周条」要把选中/今天/标记/横向翻周全部重写一遍，风险大得多。
   - 手势：`NotificationListener<ScrollNotification>`（`calendar_view.dart` 的日历分支）→

     1. **只认竖向通知**：`TableCalendar` 内部是横向翻页的 `PageView`，它的通知同样会冒泡

### 8.10.1 真机抓出来的两个免打扰 bug（都已修）

1. **按钮换段不走免打扰同步**：暂停/继续、跳过休息这三个按钮里有
   `_lastPhase = _engine.phase;`（**手动对齐**），于是 `_onTick` 里"段变了"的判断
   永远不成立 —— 免打扰同步只挂在那个判断上，这条路就被跳过了。
   实测：工作中点「暂停」，`mInterruptionFilter` 仍然是 **4**（本该还原成 1，让用户能收到通知）。
   修法：两个按钮里补调 `_syncDoNotDisturbForPhase()`；另外在 `_onTick` 里**再加一道
   与段无关的对齐**（只看「当前该不该静音」，`_lastSilenced != _engine.isWorking` 才动手），
   这样以后任何路径换段都会在 1 秒内被纠正，不会再有人漏调。
2. **`enableForFocus()` 会把还原记录清掉**：它原来是"当前已经是完全静音 → 清掉保存的档位"。
   问题是**我们自己刚设的静音**也满足这个条件 —— 上面那道对齐一旦二次调用它，
   记录就没了，结束时 `restore()` 变成空操作，**用户手机会一直静音**（最不能出的事故）。
   修法：已静音时直接返回，**绝不清记录**（用户自己开的免打扰本来就没有记录可清）。
   → 这一条是"为了兜底而加的第二道同步"逼出来的隐患，真机复验时确认：结束专注后
   `mInterruptionFilter` 回到 **1**，手机没被留在静音。

## 9.1 横向翻页阈值调高（"老是划错"）

- 原实现：月份翻页走 `TableCalendar` 内部 `PageView` 的 `PageScrollPhysics` ——
  手指一带就翻，还可能一口气翻好几页；库也没暴露这个 physics。
- 现在：把内置横向手势关掉（`availableGestures: AvailableGestures.verticalSwipe`，
  竖向"整月 ⇄ 一周"保留），自己套一层带阈值的 `ModSwipePager`
  （`lib/mod/calendar_paging.dart`）：**划够 90 逻辑像素**（约屏幕宽度的 1/4）才翻；
  快速轻扫（≥40px 且 ≥900px/s）也算。翻页本身用纯函数 `shiftedFocusedDay`
  （月视图整月挪、周视图整周挪，**日期按目标月长度收口**，1 月 31 日往后 → 2 月 28 日）。
- ⚠️ **两个只有真机才会暴露的坑（都踩过了）**：
  1. **必须用 `GestureDetector` 而不是 `Listener`**：首页 5 个标签是外层一个 `PageView`，
     它也在抢横向滑动。`Listener` 只是旁听、不参与手势仲裁，长距离横划会被外层抢走 ——
     实测**真的会误切到「待办」标签**。用横向拖拽识别器把这一片占住，外层就拿不到了。
  2. **`adb input swipe` 的坐标是设备像素，Flutter 指针坐标是逻辑像素**（1080÷3=360）。
     所以 `input swipe ... 220px` 在代码里只有 73 逻辑像素 —— 够不着 90 的阈值，
     看上去就像"手势完全没生效"。我在这个换算上绕了好几圈，最后靠**把计数画在屏幕上**
     （`DIAG down=1 up=1 dx=-73`）才定位到：手势一直是好的，是我测试划得太短。

## 9.4 横幅通知的「划掉」点了没反应（真 bug）

- 用户原话：「横幅通知点划掉没有反应，只能点击延迟」。
- 原因（读插件源码确认）：`showsUserInterface: false` 的按钮**不会把 App 拉到前台**，
  响应只会送到**后台 isolate**（插件为它单独起一个引擎执行
  `onDidReceiveBackgroundNotificationResponse`）—— 而后台 isolate 碰不到前台界面，
  于是通知取消了、**全屏闹钟照样响**。「延迟提醒」是 `true`（会把 App 拉起来），
  所以一直能用 —— 这个"只有一条好用"的现象正好印证了机制。
- 修法：
  1. 闹钟模式的「划掉」改成 `showsUserInterface: true`，让它走前台回调
     （`TaskReminder.actionsFor(mode)`，有单测钉住）；通知模式没有全屏闹钟要停，
     保持 `false`（点它不必把 App 弹出来）。
  2. **闹钟页原来根本不监听 `TaskAlarmCenter`** —— 就算清掉中心，页面也不会关、
     铃声一直响（铃声是在 `dispose` 里停的）。现在它监听中心，被别处清掉就自己关掉；
     并加了"只 pop 一次"的守卫（否则 `clear()` + 自己 pop 会把下面那一页也弹掉）。
  3. 顺手注册了后台按钮的入口函数（`@pragma('vm:entry-point')`），
     免得那种按钮点下去静默消失、插件还白起一个引擎。
- ⚠️ 这条**只做了代码级 + 单测级验证**（真机上要等一条真的闹钟到点；我这套 adb 自动化
  造不出"精确 2 分钟后响的提醒"）。一分钟自测法：待办里新建一条**提醒型**待办、
  时间设成 2 分钟后，等横幅弹出 → 点「划掉」应当立刻停响并收起。

## 11.9 ★ 小组件"点了没反应"的真凶：后台被电池优化限制（已定位 + 已解决）

这一条值得单独记，因为**根因不在小组件，也不在桌面**。

### 现象
- 桌面点方框：进 App 看，待办**确实完成了**；但**小组件画面纹丝不动**（连重绘的迹象都没有）。
- 而在 App 里操作 → 小组件的画面**会**跟着变。

### 定位过程（探针逐层切开）
1. `onAction 收到勾选` ✓、`queued=true` ✓、`update/updateAll 已请求` ✓ —— **动作与数据全对**；
2. 画面仍不变 ✗ —— 于是排除"勾选没生效""快照没更新"这两层；
3. 抓系统日志发现：点击后**只有 `AppWidgetServiceImpl.resetAppWidgetProviderInfo`**（系统收到请求 ✓），
   而 **Glance 的 `androidx.glance.session.SessionWorker` 一次都没跑** ✗ ——
   那是个 **WorkManager 任务**；
4. **决定性实验**：`adb shell dumpsys deviceidle whitelist +xyz.nosig.celechron.mod`
   把它加进电池优化白名单 → 再点 → 被卡住的任务**立刻执行**：
   `I/WM-WorkerWrapper: Worker result SUCCESS for Work [ ... tags={ androidx.glance.session.SessionWorker } ]`
   → 小组件画面**当场变成正确的条数** ✓✓✓

### 结论
**小组件的重画依赖 Glance 的会话任务（WorkManager），而 App 被系统"电池优化/后台限制"
管着时，这个任务在后台根本不会被调度** → 数据更新了、画面永远不重画。
App 在前台时任务能立刻跑，所以现象就是"**进 App 就正常、在桌面点就没反应**"。

**这和"闹钟不响"是同一个根因**（我们那个「闹钟可靠性」面板讲的就是这件事）。
→ 待办：把这条也写进那个面板 + 更新日志里说明（见 BACKLOG）。

### 本轮同时做的两件事
- **`LazyColumn` → 普通 `Column`**（`TodoWidget.kt`）：Glance 的 LazyColumn 是适配器型集合
  （日志里的 `lazyCollection=2`、`ListAdapterCallbackTrampoline`），换掉它让小组件变成
  一份普通 RemoteViews，重画链路更短更可预测。代价：**失去滚动**，超出高度会被裁
  （列表最多 6 条，小组件本身可拉伸）。
- **定向 `update(glanceId)` + `updateAll` 两条都发**，并把两处 SharedPreferences 写入
  从 `apply()` 改成 `commit()`（排除"写还没落就重画"）。
- **探针保留**：`adb logcat -s ElychronWidget` 能看到"收到勾选 / queued / 推快照的条数与 id"，
  下次同类问题一步就能定性，不用再从零猜。

### ★ 后续决定：**尘封这个小组件**（2026-09-15 深夜，用户拍板）

定位清楚之后用户的要求是「**实在修不好就尘封**」，而结论是：

## 11.11 ★ 「更新后半坏登录态」的成因与修复（已修，含成因）

用户原话（反馈过很多次的老毛病）：

> 基本上每次推送更新的时候登录态会变成一种诡异的样子，显示"已登录"但是没有学号，
> 同时学业页面刷新不出来。退出登录后再次重新登陆时不会保存上次的账号密码，
> 重新登陆之后一切恢复正常。

### 成因：两套存储的存活期不一样

- **`isLogan`（以及课程、成绩等）跟着 `Scholar` 存进 Hive 数据库** —— 覆盖安装后还在 ✓；
- **`username` / `password` 存在系统密钥库**（`FlutterSecureStorage`，见
  `database_helper.dart` 的 `getScholar/setScholar/removeScholar`）——
  某些 ROM / 机型在覆盖安装后**读回 null（且不报错）** ✗。

于是 `Scholar` 从数据库恢复时无条件 `isLogan = true`（`scholar.dart` 恢复路径的最后一行），
App 就"认为自己登录着"：不做重新登录、但每次刷新都必然失败 →
用户看到的就是那个"诡异的样子"。**学业页还因此每 20 秒崩一次**（`Scholar.isGrs` 里的
`username!`，见 11.8）——**11.6 与 11.7/11.8 是同一个现场**。

### 修复

在 `main.dart` 注入 scholar 之前做一次纠正（**注入之前**，全 App 都会看到纠正后的状态）：

```dart
final credentialsMissing = username.isEmpty || password.isEmpty;
if (restoredScholar.isLogan && credentialsMissing) {
  restoredScholar.isLogan = false;      // 别再去跑注定失败的自动刷新
  restoredScholar.sessionInvalid = true; // 设置页会给出「重新登录」入口（已有该 UI）
}
```

并打一行 `debugPrint`，把"凭据缺了哪一项"记进日志，方便下次直接确认是不是同一回事。

### 还差一步（需要用户拍板）

「记住的账号密码」（`mod_last_*`）**也存在同一个密钥库里** —— 所以密钥库读不出来时，
它同样读不出来，这就是"退出重登时不会预填"的直接原因。
要让它真正挺过更新，只能**换一个不受密钥库影响的存储**（App 私有目录 / 数据库），
而那意味着**密码以可解形式落在应用私有存储里**（虽然只有本机、只有 App 自己能读，
但终究不如密钥库）。这是个**安全与便利的取舍**，等用户决定：
- 要"永远能预填" → 把 `mod_last_*` 一并镜像到数据库（并在文档/设置里讲清楚）；
- 只要"更安全的失败" → 保持现状，但登录页在预填失败时明确提示"上次的账号没能读出来，
  请手动输入"。

### ★ 用户拍板：改成"永远能预填"（2026-09-15 深夜，已实现）

用户选择前者：**另存一份到数据库，永远能预填**。实现：

- 新增独立盒子 `dbAccount`（`DatabaseHelper.accountBox`），键 `lastUsername` / `lastPassword`；
- `rememberAccount` **两处都写**：系统密钥库（首选，加密）+ 数据库（回退副本）；
- `rememberedAccount` **先读密钥库，读不到再退回副本** —— 正常情况下用的仍是加密存储，
  只有在密钥库"失忆"时才用到副本；
- `forgetAccount` 两处一起清（退出登录**不**调用它，仍然保留预填）。

**取舍写在代码注释和这里，别以后当惊喜发现**：数据库那份是**可解形式**，
存在应用私有目录里，只有本机能读，但终究不如密钥库。安全与便利之间用户选了后者。

# 十二、2026-09-16：一次真实数据事故的完整记录（「App 打不开」→ 数据抢救）

> 这一节必须写，而且必须写清"为什么"：这个 bug 是**我们自己**引进的，
> 现场表现又是最吓人的那种（App 完全打不开、数据看起来全没了）。
> 以后任何人碰 Hive adapter，都应该先读这一节。

## 12.1 事故是怎么发生的（我的锅，写明白）

- **起因**：给待办加「课程归属」时，`Task` 加了 `@HiveField(26)`，
  adapter 的 `read`/`write` 也都加了 —— 但**头部那个"字段计数"字节忘了同步**
  （声明 **23** 个字段、实际写了 **24** 个）。`FocusSession` 同样犯了（11 → 12）。
- **后果（关键）**：Hive 写入时**不校验**计数，所以每次保存待办都会安静地写下一个
  "多一对字节"的坏帧 —— 一切正常，直到**读取**：
  列表读取器把多出来的那个 `26` 当成了**下一个待办的 typeId**
  → `HiveError: Cannot read, unknown typeId: 26` → `openBox` 抛错
  → `main()` 在 `runApp` 之前就死了。
- **用户看到的**：进程活着、日志里没有任何异常、first frame 永远不来；
  系统侧记为 `AppBootFail` + 一条 ANR。也就是「Elychron 打不开了」。
- ★ **教训（一句话）**：Hive 的字段计数是**手写**的。加字段必须同时改三处 ——
  **① 模型的注解 ② adapter 的 `read`/`write` ③ 头部那个 `writeByte(n)`**。
  而且还必须是**追加**（新字段 id 排在最后），一旦重排或插队就是同一类事故。

## 12.2 修复：先让 App 能打开，再谈数据

1. **把计数改对**：`deadline_adapter.dart` 23→24、`focus_adapter.dart` 11→12。
2. **开机自我修复** `openBoxResilientImpl`：开机先记一笔"正在开 X"、开好了再记一笔
   "X 开好了"；下次启动若发现"记了没完成"，说明上次就是死在 X 上
   → **把它整份留档（`.damaged-<时间戳>`）再挪走**。**数据一条不删。**
   - 为什么不用"先试开、失败再修"：**Hive 会缓存"打开失败"的 future** ——
     第二次 `openBox` 拿到的是同一个失败结果，这条路根本不成立（我第一次修复就这么白忙的）。
3. **锁超时兜底**：`openBox` 拿不到锁时会**无限等待**（另一个 isolate 握着，或上次被杀留下死锁）。
   现在最多等 8 秒，超时就删掉 `.lock` 重试一次。
   理由：启动这一刻我们这一侧没有别的写手，**"让用户彻底打不开"的代价远大于极小概率的并发写**。
4. **密钥库保险丝** `secureStorageOrNull`：`init()` 里原本有一个**没有 try、没有超时**的
   `await secureStorage.readAll(...)`，平台侧不返回，`main()` 就永远走不到 `runApp`。
   现在最多等 3 秒，超时或抛错都当"读不到"。密钥库再坏也不能让 App 打不开。

# 十三、2026-09-16（第二轮）：用户报的「点成绩卡片就卡死」+ 两条小改进

## 13.1 ★ 「点击成绩卡片任意位置会卡死」—— 已修，成因完整记在这里

**用户原话**：「全版本点击成绩卡片任意位置会卡死」。

**真机复现**（HUAWEI OCE-AN50 / Android 12，正式包，一摸一样）：

1. 点「学业」页的**成绩卡片** → 立刻一条
   `RangeError (length): Invalid value: Valid value range is empty: 0`；
2. 之后**点什么都没反应**，约半分钟后系统弹
   「**"Elychron"无响应。是否将其关闭？**」；
3. `am_anr`：`Input dispatching timed out … Waited 5000ms for MotionEvent`；
4. dropbox 里的 ANR 报告：**主线程 state=R、utm=23.5 秒、进程 CPU 116%**，
   而且栈全在 `libapp.so`（Dart AOT）里 —— **不是死锁，是主线程被烧住了**。

### 直接原因：在空列表上取下标

成绩页构建时读的是 `semestersWithGrades[semesterIndex.value]`，
而这个列表 = 「**有成绩的学期**」。新生一门成绩都没有 → 列表是空的 → 必然越界。
（这也解释了为什么"全版本都这样"：这段代码来自上游，一直如此，只是**没有成绩的人**才会碰到。）

### 放大器（关键，和"具体哪一行写错"无关）

GetX 4.7.3 `get_rx/.../rx_interface.dart` 的 `notifyChildren`：

    RxInterface.proxy = observer;      // 先设全局代理
    final result = builder();          // ← 这里抛错
    ...
    RxInterface.proxy = oldObserver;   // 夭折：永远不会执行

于是 **`RxInterface.proxy` 被永久留在一个构建失败的 Obx 上** →
之后全 App 任何一次 Rx 读取都挂到这个"死观察者"上 →
反复触发它 setState → 它每次重建都再抛一次 → **主线程 100% 空转** → 5 秒后 ANR。
（`lib/page/scholar/scholar_view.dart` 顶部早就记过同类事故：「build 出错 → 错误组件又出错 → …」
把主 isolate 烧死；这次是它的另一个入口。）

### 修法（三层，缺一不可）

1. **不让它抛**（治本）：
   - `GradeDetailController` 新增 `safeIndex` / `hasGrades`，所有下标都走它；
   - `getYearStats` / `getYearMajorGpa` / `getPairedSemesterIndex` 全部挡越界，越界返回 0；
   - 学期名 `substring(2,5)` / `substring(7,11)` 改成按长度安全取（脏数据不再崩）。
2. **正常的空状态**：一门成绩都没有时显示「还没有成绩」卡片
   —— 这是**正常状态，不是错误**，不该弹错误也不该崩。
3. ★ **兜底解毒剂**（`main.dart`）：给 `FlutterError.onError` 加一句 `RxInterface.proxy = null`。
   只要有**任何** builder 抛错，就地断掉上面那条放大链路。
   GetX 我们改不了，但它的 `proxy` 是**公开静态字段**。
   这一条和"哪一行写错了"无关，是防止**下一次**别的地方写错又把 App 烧死。

### 同一类坑的另一半（顺手一起修了）

`CourseDetailPage` 的构造函数原来是：

    course = _scholar.value.semesters
        .firstWhere((e) => e.courses.containsKey(courseId))   // ← 没有 orElse
        .courses[courseId]!;

只要那个 courseId 不在课表里就抛 `StateError: No element`，而且是在
`Navigator.push` 的路由构建里抛的 —— 后果和上面完全一样（页面打不开 + Obx 中毒 + 卡死）。
**哪些课会找不到？**最典型的就是**成绩卡片**点进去：军训、体育、通识课这些
**没排进课表**的课照样有成绩。现在改成找不到就显示「课表里没有这门课」。
（顺带：`createSessionCard` 原来在 build 里对 `course.sessions` **就地排序**，
