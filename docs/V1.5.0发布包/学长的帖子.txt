## 一、关于这次更新

之前 Tixer 在 Elychron v1.4.1 的更新帖里提到过，后续会推出 iOS 版本。现在这件事总算有了下文。

这次我和 Tixer 一起完成了 Elychron v1.5.0.1 的开发，我主要负责 **iOS / iPadOS 移植**及相关原生功能适配，另外还加入了普物实验课表同步。两部分内容其实没什么直接联系，只不过正好都在这次更新里完成了，索性一起介绍。

目前 iPhone 和 iPad 已经可以运行 Elychron，原有的课表、成绩、考试、待办、专注模式以及 AI 整理等功能都得到了保留。在此基础上，我也为苹果设备补充了一些原生功能，包括适配 iPad 的界面、系统分享和 **AlarmKit** 闹钟。毕竟既然移植到了 iOS，总不能只是把 Android 版原样搬过来，最后得到一个能打开、但不太像苹果 App 的东西。

普物实验课表同步则是面向所有平台的功能。现在可以直接从学校的实验选课系统读取实验安排，并整合进 Elychron 原有的课表，不必再单独打开网页查看。这部分我放在第三节详细介绍。

先说明一个比较遗憾的地方：目前 iOS 版还没有上架 App Store。因为暂时没有可以用于正式发布的 Apple Developer Program 开发者账号（因为贫穷），现阶段只能先提供 IPA 安装包，由大家自行签名安装。

好在整个过程不需要会写代码，也不需要 Mac。有 Windows 电脑和自己的 Apple 账号就能尝试安装，后面会放一份从零开始的教程。

## 二、**iOS / iPadOS 移植**

### 1. iPad 终于有了自己的界面

先说最容易看出来的部分。

虽然 iPhone 和 iPad 使用的是同一个应用，但在 iPad 上简单放大手机界面显然不太合适。尤其是横屏使用时，屏幕宽了不少，原来的底部导航和一些弹窗却还是手机上的样子，多少有点浪费这块屏幕。

所以这次单独调整了 iPad 的布局。当窗口足够宽时，原来的底部导航会变成五栏侧边栏，课表、待办等页面可以直接在左边切换，主要内容则集中在右侧。如果缩小窗口，或者使用 iPad 的分屏模式，界面又会自动切换回适合窄屏的布局。

此外，弹窗、表单和键盘交互也一并做了适配，输入框不会动不动横跨整张屏幕，弹出键盘时也会尽量避开正在操作的内容。

现在 iPhone 和 iPad 共用一份 IPA，安装时不需要专门挑选平板版本。

### 2. 苹果原生闹钟

待办提醒应该算是 Elychron 比较常用的功能之一，这次也接入了 Apple 的 **AlarmKit** 原生闹钟框架。

现在创建或编辑待办时，可以选择使用普通通知，也可以设置原生闹钟。对于一般的课程、日程，用通知提醒就够了；但如果是一件特别不想忘记的事，原生闹钟显然更合适一些。

这两种提醒方式可以分别选择，不需要把每条待办都设置成闹钟。

原生闹钟还与待办状态绑定：修改待办时间时，闹钟会跟着重新安排；完成或删除待办后，对应的闹钟也会取消。这样至少不会出现事情早就做完了，过几个小时手机又来提醒一次的情况。

不过 **AlarmKit** 仅支持 **iOS / iPadOS 26 及以上版本**，并且需要授予权限。旧系统或无法使用原生闹钟时，应用会使用普通通知作为替代，实际提醒效果也会受到通知权限、专注模式等系统设置的影响。

另外，待办详情中还提供了独立的一次性闹钟。它与待办状态不绑定，设置之后需要自行管理，和前面说的自动同步闹钟有所区别。

### 3. 直接从微信、浏览器分享内容

这一部分我个人觉得还是比较实用的。

比如在微信里看到老师发的一段作业要求，或者在浏览器里打开了一份之后要用的资料，现在可以直接点击系统分享，选择「存到 Elychron」，把文字、图片或文件送进应用。

分享内容会先进入 Elychron 的收件箱，之后可以拿它创建一条新待办，也可以追加到已有待办的描述或附件中。省去了先下载文件、再打开软件、再找地方导入的过程。

这项功能使用的是苹果原生的 Share Extension 和 **App Group**。简单理解，前者让 Elychron 出现在其他 App 的分享菜单中，后者负责把接收到的内容交给主应用。

也正因为如此，自签安装时需要保留对应的应用扩展以及数据共享权限。如果签名工具没有正确处理这些内容，主应用虽然可能正常打开，分享功能却不一定能用。后面的安装教程会特别提一下。

### 4. 登录与其他功能

其他部分主要是对原有功能做苹果平台适配。

统一身份认证可以在 iOS / iPadOS 上使用，登录凭据通过系统 **Keychain** 保存，相关的权限配置和认证提示也进行了调整。原有课程、成绩、考试、待办等页面继续使用 Elychron 的数据与业务逻辑，因此不同平台的主要使用方式基本一致。

待办和校园卡等小组件也有对应的苹果平台实现。除此之外，日历、PTA、图书馆等功能同样保留，不过部分功能需要学校账号、校园网络或相应系统权限，具体使用情况还要看设备环境。

总的来说，这次移植的目标并不是再做一个只有课表的精简版，而是尽可能把现有 Elychron 搬到苹果设备上，同时补齐苹果平台应有的功能。

## 三、普物实验课表同步

接下来是这次更新的另一项主要内容，也是我觉得日常使用中比较能省事的一个功能。

普物实验的课程安排一直有一点特别：虽然它也是正经的教务课程，但实际实验项目、选课时间和排课信息都在单独的实验选课系统里。教务系统里看到的时间，不一定就是最后实际去做实验的时间。

这就导致每次想确认某个实验究竟安排在哪天，还得再打开一次实验选课网站。如果中途改了期，之前记下来的时间也未必还对。课表软件都装了，最后却还是要靠两个网页互相对照，我觉得多少有点失去整合课表的意义。

所以这次直接把**普物实验选课系统接进了 Elychron**。

使用方法并不复杂。进入 设置 → 教务 → 普物实验 → 登录选课系统，在打开的学校官方页面里正常登录，然后进入「我的课表」，点击应用右上角的「完成」，就可以读取当前学期已经选择的实验课程。

这里同步的是当前学期的全部已选实验，而不只是某一门课。完成之后，实验安排会整合进 Elychron 原有的课表、课程详情和日历中，不会额外生成一堆待办。打开课程详情，也能看到对应实验的日期与起止时间。

不过光把实验时间读回来还不够。教务系统和实验系统毕竟是两套数据，万一同一门课程给出了两份不同的安排，总不能随便挑一份覆盖掉另一份。

因此我还加入了 **课表来源选择**。

首次同步之后，可以自行选择继续使用教务系统的课表，或者改用实验选课系统里的实际安排。如果选择实验选课系统，应用会要求确认实验课程与原有教务课程的对应关系，再将实验安排应用到正确的课程上。

这样处理之后，变化的只是对应课程的上课时间，原有的学分、成绩、考试信息仍然保留，其他课程也不会受到影响。教务系统的原始数据不会被直接改写，哪天不想使用实验来源了，也可以随时切回去。

我认为这一点还是有必要的。毕竟整合课表本来是为了减少需要核对的信息，总不能整合完之后，连哪份数据才是原来的都分不清了。

后续同步也做了相应处理。假如某次实验改期了，重新同步时会更新原有安排，而不是在课表上再塞进一门一模一样的课。教务课表正常刷新之后，实验安排也会重新整合进去。遇到网络异常或登录失效，则会尽量保留已经保存的课程数据，不会因为一次请求失败就清空课表。

应用支持手动立即同步，同时也设置了自动同步的请求间隔，避免频繁访问学校服务器。

这里需要感谢开源项目 5dbwat4/zjuphylab.ics，这次开发参考了其中的接口、字段映射和实验时长处理方案，并在此基础上实现了 Elychron 内的课程读取、来源切换和数据整合。目前相关自动化测试已经通过，iPad 上的实际登录、同步与来源选择也进行了验证。

有两个使用上的注意事项需要单独说一下。

第一，普物实验选课系统属于**校园内网服务**。 同步时需要连接校园网络，或者使用能够正常访问学校内网的 VPN。手机自身必须具备访问条件，电脑开了 VPN 并不会让手机自动获得内网访问权限。

第二，实验时间仍以学校官方系统为准。 如果网站没有提供准确的实验结束时间，Elychron 会使用默认时长进行估算。这种情况下，建议还是核对一下官方安排。

对已经选了普物实验的同学来说，现在至少不用在教务系统、实验选课系统和自己的日历之间来回切了。

## 四、测试与使用说明

目前 iOS / iPadOS 版本已经完成了 iPhone、iPad 模拟器上的安装与界面检查，也进行了部分真机测试。

真实账号登录、图片分享、普通通知、**AlarmKit** 原生闹钟响铃，以及 iPad 上的普物实验课表同步都已经有成功验证记录。相关的 Flutter 自动化测试、原生组件测试和 IPA 构建检查也已经通过。

当然，这并不意味着所有功能都在全部设备和系统版本上完成了验收。部分小组件、快捷指令、系统日历导出、旧版本系统下的通知回退以及后台刷新等功能，还需要更多实际使用环境下的反馈。

当前版本最低支持 iOS / iPadOS 15，需要使用原生闹钟的同学则必须升级到 iOS / iPadOS 26 或更新版本。

如果使用过程中发现问题，欢迎附上设备型号、系统版本以及具体操作步骤反馈，方便定位和复现。

## 五、iOS / iPadOS 安装与免费自签教程

终于到安装部分了。

目前没有 App Store 下载渠道，需要通过 IPA 自签安装。下面以 Windows + iloader 为例，从下载开始讲完整流程。

如果之前完全没有接触过 iOS 自签，也可以直接照着下面的步骤操作。**不需要 Mac、不需要 Xcode**，也不用自己编译项目。

### 1. 下载 IPA 安装包

首先打开 Elychron v1.5.0.1 的 GitHub Release 页面：

https://github.com/Elyyyyyyyyxer/Elychron/releases/tag/v1.5.0.1-ios

在页面下方找到 Assets，下载：

**Elychron-1.5.0.1-ios.ipa**

这就是完整的 iOS / iPadOS 安装包，iPhone 和 iPad 通用。

同一个页面还提供了 .ipa.sha256 校验文件，以及 SELF_SIGN_GUIDE.md 安装说明。如果担心文件在下载过程中损坏，可以通过 SHA-256 校验其完整性。

IPA 可以理解为苹果平台的应用安装包，但它不能像 Windows 的 exe 一样双击就装。当前发布的是需要自行签名的 IPA，因此还需要下面几个步骤。

### 2. 安装 iloader

这里使用开源的 iloader 进行安装。

官网：

https://iloader.app/

GitHub：

https://github.com/nab138/iloader/releases/latest

进入官网或 GitHub Release 页面，下载对应的 Windows 版本，按照安装程序的提示完成安装。

为了让电脑识别 iPhone 或 iPad，还需要相应的苹果设备驱动，通常可以通过安装 iTunes 及其相关组件获得。

如果电脑上已经安装过 iTunes，可以先直接尝试连接设备；如果后面始终识别不到手机，再回来检查驱动。

### 3. 用数据线连接设备

使用能够传输数据的数据线，把 iPhone 或 iPad 连接到电脑，保持设备解锁。

第一次连接时，设备一般会弹出「要信任此电脑吗」，点击「信任」，再输入锁屏密码确认。

打开 iloader，检查软件能否识别设备。

如果没有识别到，可以依次确认设备是否解锁、数据线是否支持传输、是否已经点击信任，以及电脑是否安装了正确的驱动。

### 4. 导入 IPA 并签名

设备连接成功后，在 iloader 中选择需要安装的设备，按照工具的界面提示登录自己的 Apple 账号，并完成相应验证。

随后导入之前下载的：

**Elychron-1.5.0.1-ios.ipa**

使用普通的**免费 Apple 账号**即可进行个人设备自签，不需要额外购买付费开发者会员。

这里需要特别注意 Elychron 的两个应用扩展：

* **ShareExtension**：负责接收其他 App 分享的内容。
* **WidgetExtensions**：负责桌面小组件。

如果工具提供了保留或移除应用扩展的选项，尽量保留它们。同时，相关功能依赖有效的 **App Group** 共享权限；部分免费签名方式可能无法完整保留这些权限，因此即使主应用可以正常使用，分享和小组件也不一定都能正常工作。

确认安装选项后，按照 iloader 的提示完成签名和安装。

另外提醒一下，Apple 账号密码、验证码等信息只应在可信的登录流程中使用，不需要发送给项目开发者，也不要把个人签名凭据交给其他人。

### 5. 信任应用并开启开发者模式

安装完成后，设备桌面上应该就可以看到 Elychron 了。

如果第一次打开时提示开发者不受信任，可以进入：

设置 → 通用 → VPN 与设备管理

找到与本次签名对应的开发者信息，按照系统提示完成信任。

对于 iOS / iPadOS 16 及以上版本，还可能需要打开：

设置 → 隐私与安全性 → 开发者模式

启用后按照系统提示重启设备，并在重新解锁时确认开启。

完成这些操作，就可以尝试启动 Elychron 了。第一次使用时，正常登录学校账号，再根据需要授予通知、闹钟等权限即可。

### 6. **七天有效期**与续签

**免费 Apple 账号**自签有一个需要注意的地方：签名通常只有**七天有效期**。

也就是说，七天后应用可能无法继续打开，需要重新连接电脑，通过 iloader 重新签名安装。倒不是每周都要重新下载和编译 App，只是签名需要定期续上。

建议使用相同的 Apple 账号和应用标识进行覆盖安装，更新前也最好通过 Elychron 自带的功能导出 JSON 数据备份。尤其不要为了续签直接卸载旧版，否则可能丢失本地数据。

如果签名已经到期，请不要继续依赖应用执行重要提醒。

目前用自签方式发布，主要还是没有正式上架条件下的权宜之计。如果有具备 Apple Developer Program 开发者账号、熟悉 App Store 上架流程，或者有相关条件的同学，欢迎私信联系，可以进一步讨论正式发布的可能性。
