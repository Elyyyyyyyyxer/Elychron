| `lib/utils/data_backup.dart` | 91 | 文件导出/导入（同一份契约，走文件而不是网络）|
| `lib/model/tombstone.dart` + `lib/mod/database_mod.dart` | — | **删除墓碑**：合并时判断「这条是被删掉的」而不是「对方新增的」|

**已经有底子的地方（很重要）**
- ✅ 数据契约是**版本化 + 传输无关**的（`DataBundle` + 墓碑），加新传输方式是**加法不是重写**；
- ✅ 已经有**两条**通路：网络（`/bundle`）与文件（导出/导入）；
- ✅ 合并逻辑有 `added/updated/removed` 统计，能如实告诉用户改了什么；
- ✅ 配对机制（token）已经有了。

**现在的缺口**
- ❌ 只同步 **待办 / 标签 / 少量设置**：`dbFocus`（专注记录）、附件文件、其它设置**都不在里面**；
- ❌ 面板是「手机当服务器」的单向心智：PC 端本质是遥控器，**不是对等端**；
- ❌ 没有**设备身份**：看不出「这条是哪台设备改的」，也没有「同步到哪些设备」的概念；
- ❌ 没有**实时推送**：现在是一次性的取/交，不会自动感知对方的变化；
- ❌ 冲突策略是**整条 last-write-wins**（靠 `updatedAt`），没有分字段合并；同一秒两边改会丢一边。

### 关于「为什么不直接把 App 装到电脑上」（用户问过，记下来）

Flutter 跨平台跨的是 **UI 层与 Dart 运行时**，不是整个 App。所以：
1. **APK 是 Android 二进制，Windows 跑不了** —— 以前能靠微软的 WSA（Windows 子系统 for Android），
   但**它已在 2025 年 3 月停止支持**；剩下的安卓模拟器体验与「顺手的桌面工具」是两回事；
2. **就算为 Windows 重新编译，插件层也过不去**，实测统计（BACKLOG 第 4 项）：
   - `workmanager`（上游自建 fork）**只支持 Android/iOS** —— 11 处
   - `flutter_local_notifications` **不支持 Windows** —— 18 处
   - `MainActivity.kt` / `ECardWidget.kt` 里的校园卡小组件、全屏闹钟、分享接收
     —— **这些功能在 Windows 上本身就不存在**，整层要重写
   - 另有 `Platform.is` 23 处、`PlatformFeatures` 抽象 11 处 —— 说明代码从没打算跨端跑
3. 真想要桌面端，**得先回答「在电脑上干什么」**：
   - 只是「看和改待办」→ **浏览器面板就是最优解** ✓（零安装、任何电脑能开、改完自动同步）
   - 「电脑上常驻提醒 / 离线重度用」→ 才值得上 Windows 客户端（工作量比面板大一个量级）
   - 好消息：`hive` / `flutter_secure_storage` / `path_provider` / `file_picker` /
     `share_plus` / `table_calendar` **都支持 Windows** ✓ 基础不是从零开始

## 三、建议的路线（每阶段都能单独交付、单独验证）

### S1：把「同步什么」补齐 + 设备身份（地基）
- `DataBundle` 加 `deviceId`、`focusSessions`、`focusWorkMinutes/focusRestMinutes/...`
- 契约**只加字段不改老字段** → 老备份文件仍能导入 ✓
- 测试：契约往返 + 合并（含墓碑、含专注记录）

### S2：面板升级成真编辑器（BACKLOG 1）
- 能改描述 / 子待办 / 标签 / 优先级 / 地点；**改步骤时间与清单分组**
- 自动拉取 + 改完自动推；显示「最后同步来自 X」
- 这是你实际用得最多的界面，值得一次做扎实

### S3：附件同步（BACKLOG 2）
- 附件按内容 sha1 命名 → 同一个面板服务加 `/attachment/<sha1>` 端点
- PC 端**懒下载**（点开才拉），手机端上传
- 需要一个「附件清理」策略（孤儿文件多久删）

### S4：跨网络 —— **两条路线都留，用户自由切换**
- 抽 `SyncTransport` 接口：`LocalHttpTransport`（现在这套，同一 Wi-Fi）
  / `WebDavTransport`（用户自配坚果云应用密码）
- **最终两条都保留**，设置里让用户选当前用哪条（或「都启用」），
  数据层完全复用 S1 的契约 ✓
- 界面要写清两者差别：局域网=**免配置、只在同一 Wi-Fi**；坚果云=**在外面也能同步、但要自己配一次**

### S5（可选）：Windows 桌面端（BACKLOG 4）
- 只有前面都稳了、并且你真的需要「电脑上常驻」再上

## 四、风险与坑（先记下来）

| 风险 | 说明 / 对策 |
|---|---|
| **半同步状态**：同步到一半断了 | 契约里有 `exportedAt` 与墓碑，重跑一次是幂等的 ✓ 但仍要测「中断后重连」 |
| **时钟不一致**：两台设备时间不一样 → `updatedAt` 比较出错 | 用「谁的时间更晚」只在**两端都改过**时用；并显示改了哪条，不静默丢 |
| **大附件**：几百张截图 | 懒下载 + 只按需拉；不整包传 |
| **扫到就改**：同一 Wi-Fi 里别人拿到 token | 每次开服务重新配对；面板显示连接设备；文档写清 |
| **学校接口限流** | 注意：**课表/成绩不进同步**就是为了避免「两台设备各拉一次还互相覆盖」|
