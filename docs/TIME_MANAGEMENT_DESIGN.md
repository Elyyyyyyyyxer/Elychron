# 时间管理重写 · 设计稿

> 状态：**设计阶段**，未写实现代码。
> 前置动作已完成：旧的「时间规划」功能（排程算法 / 接下来页 / 工作时长休息时长 / 可用时段）
> 已整体删除，见提交 `refactor!: 删除全部「时间规划」功能`。
>
> 本文回答一个问题：**待办到底该不该"规划"？** 结论是——
> **不做自动排程；改成「四种时间语义 + 专注计时」两件事。**

---

## 一、为什么要重写：问题诊断

用户的实际待办里混着四种完全不同的东西：

| 实际条目 | 真正需要什么 | 旧设计里被迫表现成 |
|---|---|---|
| 班级团建（14:20 集合 / KTV / 吃饭） | 开始前提醒 + 子待办当行程表 | 建成「截止 14:20」的 DDL |
| 三轮选课 | 到某个时刻做一件事 | DDL，勉强对 |
| 取快递 | 顺手做，别忘 | DDL 23:59，显得"很急" |
| 纳新面试 19:50–20:30（要求提前 5 分钟） | 开始前提醒 | 提醒默认锚在结束时间，得手改 |
| 写代码（正在做的事） | **计时** | **完全无法表达** |
| 备忘（想法 / 清单） | 只记着，别催 | DDL 23:59，天天"已过期" |

**关键结论：这六条里，真正需要"自动排程"的一条都没有。**

- 需要"什么时候做"的 → 只有 DDL 类，而用户自己心里有数，不需要机器排；
- 需要"现在花多久"的 → 「写代码」这一类，那是**计时器**（番茄钟），不是排程；
- 其余是提醒 / 备忘 → 只需要"别忘了"，不需要时间投入。

**旧设计的问题不是不够强，而是把四种诉求塞进一个实体，于是必须引入
「可用时段 + 课表避让 + 固定日程占位 + 预计耗时 + 二分退让」五层复杂度**，
用户既配不明白，也不知道它为什么那样排。

---

## 二、设计目标

1. **零配置可用**：不填"工作时长/可用时段"也能正常用。
2. **语义显式**：创建时选类型，而不是靠"有没有起止时间"猜。
3. **提醒锚点正确**：活动提醒在**开始前**，截止提醒在**截止前**，备忘**不提醒**。
4. **专注与规划分离**：专注回答"我现在花了多久"，与"这件事什么时候做"无关。
5. **可统计**：专注记录落库，能回答"这周写代码花了多少小时"。

---

## 三、四种时间语义（核心）

创建时**必须选一个**（用户选择 A 方案）。四种类型需要的输入不同：

| 类型 | 时间输入 | 提醒锚点 | 过期行为 | 卡片显示 |
|---|---|---|---|---|
| **活动** | 开始 + 结束 | 开始前 N 分钟（默认 30） | 结束后转入「已处理」 | `14:20 - 19:50` |
| **截止** | 截止时间 | 截止前 N 分钟（默认 30） | 过期标红，仍在「待我处理」 | `截止 09-12 23:59` |
| **提醒** | 单个时刻 | 就在那一刻 | 过期后不再提醒，可随手划掉 | `今天 09:00` |
| **备忘** | **不填** | **不提醒** | **永不过期** | 只有标题，无时间行 |

设置里各给一个「默认提前量」（活动 / 截止分开）并可全局关掉提醒。

### 数据结构

**方案（推荐）：扩展 `TaskType` 枚举，追加两个值。**

```dart
enum TaskType {
  deadline,     // 0 截止
  fixed,        // 1 活动（有起止）
  fixedlegacy,  // 2 内部用：《过去日程》副本，不在界面上暴露
  remind,       // 3 提醒（新增）
  memo,         // 4 备忘（新增）
}
```

- **追加而不是插入**：`TaskType` 以序号存进 Hive，追加新值不影响既有数据。
- `normalizeType()`（原先按"起止时间是否相同"在 fixed/deadline 之间自动翻转）
  必须**尊重显式选择**：`remind` / `memo` 不参与自动翻转。
- 日历只渲染 `fixed`（活动）与 `deadline`；`remind` / `memo` 不进日历。
- 复用既有字段，不新增时间字段：
  - 活动：`startTime` / `endTime`
  - 截止：`startTime == endTime`
  - 提醒：`endTime` 存那一刻（`startTime` 同值）
  - 备忘：不显示时间；内部仍给占位值以满足模型约束

### 提醒锚点的实现

现在：

```dart
/// 提醒触发时间：没单独设过就用截止时间。
DateTime get reminderTargetTime => reminderTime ?? endTime;
```

改为按类型取默认锚点：

```dart
DateTime get reminderDefaultAt => switch (type) {
  TaskType.fixed  => startTime.subtract(kBeforeEvent),   // 活动：开始前
  TaskType.deadline => endTime.subtract(kBeforeDeadline), // 截止：截止前
  TaskType.remind => endTime,                             // 提醒：那一刻
  TaskType.memo   => /* 不调度 */,
  TaskType.fixedlegacy => endTime,
};
```

## 四、专注（新增，独立于"规划"）

这是用户最初描述的「把时间切成工作 / 休息」——**它的正确位置是执行，不是规划。**

### 交互

```
任务详情页 / 任务卡片 → 「开始专注」
（也可以不选任务，直接开一个自由专注，比如"敲代码"）

  ┌─────────────────────────┐
  │        ╭───────╮        │
  │       ╱  42:18  ╲       │   ← 大圆环：工作时长色 / 休息时长色
  │      │   工作中   │      │
  │       ╲         ╱       │
  │        ╰───────╯        │
  │                         │
  │   第 2 轮 · 写实验报告    │
  │                         │
  │   [ 暂停 ]   [ 跳过休息 ] │
  └─────────────────────────┘
```

- 参数默认 **60 分工作 / 15 分休息**（用户选择），**设置里可调**；
- 工作 → 休息 → 工作 自动交替，可暂停、可跳过休息、可提前结束；
- 休息开始时**可选**提醒你起来走走（设置项）；
- 结束时把**真实专注时长**累加到任务的 `timeSpent`（这个 Hive 字段一直被留着，正好派上用场）。

### 数据结构（新增 Hive 类型，typeId 取 20）

```dart
class FocusSession {
  String uid;
  String? taskUid;      // 关联的待办；null = 自由专注
  String label;         // 自由专注时的名字（如「敲代码」）
  DateTime startedAt;
  DateTime? endedAt;    // null = 进行中（用于崩溃后恢复）
  Duration focusedTime; // 实际专注（不含休息）
  Duration restTime;    // 实际休息
  int rounds;           // 完成的轮数
  int workMinutes;      // 本次参数，便于回溯统计
  int restMinutes;
  bool completed;       // 正常走完 / 中途放弃
}
```

- 新增 Hive box（如 `dbFocus`）与 adapter（typeId 20，追加不影响既有类型）；
- 任务侧只累加 `timeSpent`，不改任务结构。

### 后续可做的统计（P3）

- 本周 / 本月专注总时长、日均曲线；
- 按任务 / 按标签分布（"这周写代码 12 小时"）；
- 专注轮数与中断率。

## 五、AI 生成待办也要划分类型（用户明确要求）

生成草稿时增加一个 `kind` 字段，并做**白名单校验 + 与时间字段的一致性校验**：

```json
{
  "kind": "event",                     // event | deadline | remind | memo
  "summary": "参加班级团建",
  "startTime": "2026-09-11T14:20:00",  // 仅 event 必填
  "endTime": "2026-09-11T19:50:00",
  "reminderMinutes": 60,
  "description": "...", "location": "...", "tags": [...], "subtasks": [...]
}
```

判定规则（写进提示词）：

| 原文特征 | 判定 |
|---|---|
| 有明确开始与结束的活动、会议、考试、典礼 | `event` |
| 「X 日前提交 / 完成 / 报名 / 缴费」 | `deadline` |
| 「X 点去取 / 去办 / 记得做」这类单点动作 | `remind` |
| 没有任何时间信息、只是"记着" | `memo` |

校验（解析层强制，不信任模型）：

- `kind` 不在白名单 → 按"有没有成对的起止时间"回退推断；
- `event` 必须有 `startTime < endTime`，否则降级为 `deadline`；
- `remind` 只需一个时刻；`memo` **清空所有时间字段**；
- 越界一律记 `warning` 并在预览里如实展示（沿用现有做法）。

预览界面里显示类型，并允许**一键换成别的类型**（AI 判错时用户改起来很快）。

## 六、界面改动清单

| 位置 | 改动 |
|---|---|
| 新建/编辑页 | 顶部 4 个**类型胶囊**；下方时间行随类型变化（活动两行、截止一行、提醒一行、备忘无） |

| 任务页筛选 | 现有"多选标签 + 筛选"保留，筛选里**增加「类型」一栏** |

| 设置 → 待办 | 「默认提前量（活动 / 截止）」「专注参数 60/15」「休息时提醒我」 |

## 七、数据迁移

| 旧数据 | 处理 |
|---|---|
| `type == fixed` 的任务 | → **活动**（语义一致，无操作） |
| `type == deadline` 的任务 | → **截止**（语义一致，无操作） |
| 实际上属于"提醒 / 备忘"的旧 DDL | **不猜**：保持为"截止"，由用户按需改成提醒/备忘 |
| `timeSpent` | **改为专注累计**，字段复用（Hive 序号不变） |
| `timeNeeded` / `isBreakable` / `blockArrangements` | 已无用途；**保留字段**，等后续统一迁移时清理（它们是 Hive 按序号存储，直接删会让后续字段错位） |
| 旧 `flowList`（排程结果） | 课程/考试项仍有用（iOS 小组件读它）；旧的 `PeriodType.flow` 项可一次性清理 |

## 九、明确不做的事（避免重蹈覆辙）

- ❌ 自动排程（把任务塞进空闲时段）—— 用户需要时自己决定，机器不猜；
- ❌ 「可用工作时段」「预计耗时」这类必须先配置才能用的东西；
- ❌ 让一个实体同时表达"要花多久"和"什么时候做"；
- ❌ 排不下就静默失败（宁可什么都不做，也不要给出看不懂的结果）。
