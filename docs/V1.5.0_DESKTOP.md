### ⚠️ 运行被 Smart App Control 拦住了

第一次跑是成功的（界面截图见下），但**重新构建之后**启动被系统拦：

    An Application Control policy has blocked this file

事件日志（Microsoft-Windows-CodeIntegrity/Operational）里写得很明确：

    Smart App Control Block Details
    ... 学习资料\celechron魔改\Celechron\build\windows\x64\runner\Release\Elychron.exe
    that did not meet the Enterprise signing level requirements

这台机器开着 **Smart App Control**（`VerifiedAndReputablePolicyState = 1`）。
它按"文件哈希有没有信誉"放行，而**本地刚编译出来的未签名 exe 没有信誉**，
再赶上网络查不到（这台机器访问微软服务时常超时），就直接拦。

三条路，你挑：

1. **关掉 Smart App Control**（设置 → 隐私和安全性 → Windows 安全中心 →
   应用和浏览器控制 → 智能应用控制 → 关闭）。
   注意：这个是**单向开关**，关掉之后要重装系统才能再打开 —— 你自己权衡。
2. 给 exe 做代码签名（自签名不行，SAC 只认受信任的商用证书）。
3. 不在这台机器上跑：构建产物拷到别的电脑/虚拟机验收。

## 七、桌面提醒音（2026-09-19 拍板）

用户决定：「取消掉 DING 的声音，反正系统自带的声音够用」，同时把爱莉原声做成小彩蛋。

| 模式 | 声音 | 怎么切 |
| --- | --- | --- |
| **系统提示音（默认）** | Windows Toast 自带的通知音，我们**不放任何音频** | 默认就是它 |
| **爱莉原声（彩蛋）** | `assets/sounds/ely_hi.mp3`（1.29s，第一句） | 设置 → 桌面端 → **长按**「测试提醒（DING）」 |

实现要点：

- `lib/platform/desktop_alert_sound.dart`：偏好存 optionsBox（`desktopAlertSound` = system | voice）
- `DesktopNotify` 只在选到 voice 时才自己放音频，其余交给 Toast 的原生提示音
- **原声不进仓库**：`.gitignore` 里排掉了 `assets/sounds/ely_hi.*`（版权）；
  用项目外的 `import_voice.ps1` 从原始音轨裁出来：
  先读音轨（silencedetect 找句子边界），再截第一句、两端淡入淡出、响度归一到 -16 LUFS
- 原来的自制 DING 音（`assets/sounds/ding.wav`）以及它的合成脚本已删除

## 八、分组底色（2026-09-19）

用户反馈：「设置页面的背景还是灰色的」「我强烈怀疑还有很多页面也没有改」。

根因：`CupertinoListSection` 的 `backgroundColor` **默认就是分组灰**
（不是页面底色的问题）。所以之前只改脚手架底色，看到的那片灰其实是分组块自己画的。

修法：新增 `lib/design/page_background.dart` —— 桌面端返回系统白、手机端保持分组灰，
然后：
1. 10 个页面的**脚手架底色**（11 处）改走它；
2. 7 个文件里 **25 处 `CupertinoListSection`** 显式传 `backgroundColor: pageBackground(context)`。
手机端行为完全不变（还是分组灰），桌面端整页统一白。
