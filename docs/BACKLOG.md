## 一、功能

### 1. 局域网面板美化 + 更像 PC 客户端

- **现状**：面板（`lib/mod/lan_panel.dart`）是能用的素净样式，功能上只支持
  看待办 / 打钩 / 删除 / 新建 / 导出 / 导入。
- **以后要做**：视觉重新设计；支持编辑描述、子待办、标签、优先级、地点；
  也许加个看板/日历视角。
- **为什么先不做**：功能先跑通更重要；面板是纯前端单文件，改样式随时能改，不欠技术债。
- **触发条件**：局域网同步实际用起来、觉得「能用但难看」的时候。

### 2. 附件也跟着同步

- **现状**：`DataBundle` 只同步待办与标签，**不同步附件文件**。电脑面板上看到的
  附件条目在手机上有，但文件本身不会传。
- **以后要做**：附件按内容 sha1 命名，用同一个 HTTP 服务提供下载/上传端点，
  PC 端按需懒下载（不一次性全拉）。
- **为什么先不做**：附件是大文件，传输/断点/清理策略要单独设计，
  先让「文字待办」同步站稳。
- **触发条件**：用户反馈「照片/文件只能在手机上看」的时候。

### 3. WebDAV 作为可选的跨网络同步

- **现状**：只做了局域网直连（必须同一 Wi-Fi）。
- **以后要做**：`WebDavTransport`，让用户填**自己的**坚果云应用密码，
  实现真正的「在外面也能同步」。
- **重要澄清**：用户填自己的账号密码是**完全合规**的标准 WebDAV 客户端做法；
  不行的只是把**开发者自己的**账号密钥内置进 APK 给所有人共用。
- **为什么先不做**：对师生推广来说「注册坚果云 + 生成应用密码」门槛太高，
  不适合做默认路径；但作为**可选高级功能**很有价值。
- **触发条件**：局域网同步满足不了「不在同一 Wi-Fi 也要同步」的需求时。
- **工程上很便宜**：数据层是传输无关的（`DataBundle` + `DataMerge`），
  加一个 transport 是加法，不是重写。

### 4. Windows 桌面客户端（形态 B）

- **现状**：只做了形态 A（手机当服务器 + 浏览器面板）。
- **以后要做**：`flutter build windows` 出真正的桌面端，手机⇄电脑 都是 App。
- **主要障碍（已实测）**：
  - `workmanager`（上游自定义 fork，只支持 Android/iOS）**11 处**
  - `flutter_local_notifications`（不支持 Windows）**18 处**
  - 好消息：上游已有 `PlatformFeatures` 抽象（11 处）、`Platform.is` 23 处，
    基础不是从零开始
  - 已确认支持 Windows 的：`flutter_secure_storage`、`path_provider`、
    `file_picker`、`share_plus`、`qr_flutter`、`hive`、`table_calendar`
- **为什么先不做**：工作量比形态 A 大一个量级，而形态 A 已经能解决「电脑上看待办」。
- **触发条件**：真的需要在电脑上离屏使用（比如桌面上常驻提醒）时。

### 12. ~~标签库曾被清空的历史问题~~（已查明并修复）

> **已结案**：根因不是"被清空"，而是**标签库从来没有被这些来源写入过**——
> 只有「标签管理页编辑」「选择器里新建标签」「导入数据」三条路径会写库，
> 而 **AI 生成待办时直接给任务设标签**、局域网同步合并、以及旧数据里的标签
> 都只存在于待办身上。表现就是：筛选器看得到（它取的是「标签库 ∪ 待办标签」），
> 标签管理页和标签选择器却是空的（它们只读标签库）。
>
> 修复：`lib/mod/tag_harvest.dart` 做标签库自愈——TaskController 初始化时
> 把待办（含子待办）身上的标签补进库；AI 应用草稿时也会记住用过的标签。
> 这样 AI 复用已有标签的提示词也才真正有料可用。

- **现状**：早期发生过两次标签库被清空，当时的处置是加防护
  （`setTagLibrary` 拒绝空写入、标签管理页保存时与加载值做比较）并恢复了数据。
  **根因没有查明**，之后也没再复现。
- **以后要做**：如果再复现，抓 logcat + Hive 状态查一次。
- **为什么先不做**：无复现路径，盲改反而有风险。
- **触发条件**：**再次复现时**。

  1. 官方同时提供便宜档与贵档时，**哪个更适合本应用**（`/models` 只给名字，不给语义）

- **代价**：需要有人维护这份文件；应用多一次"只拉静态文件"的请求（不含任何用户数据）。
- **触发条件**：
  - 官方出现"名字没变但行为/价格变了"的情况时
  - 或者我们发现要在代码里临时加特例才能兼容某个模型时
  - 或者要开始按模型能力切换功能（比如只对多模态模型开放"截图识别"）时
- **接口建议**：`GET https://raw.githubusercontent.com/<repo>/main/model_manifest.json`，
  结构 `{ "updatedAt": "...", "recommended": "deepseek-flash", "avoid": [...], "renames": {...} }`，
  拉取失败就完全忽略（本地解析结果照常用）。

## 五、专注（P3/P4）留下的

### 20. 专注的「休息提醒」在后台 / 锁屏时不会响 ★ 建议尽早修

- **现状**：休息提醒是在页面每秒 tick 到「工作段走完」的那一刻，当场调
  `TaskReminder.showFocusRestNotice()` 弹一条通知。App 在前台时没问题，
  但**锁屏或切到后台后，Dart 定时器会被系统挂起**，那一秒根本不会到来 ——
  等用户回到前台时，它才补算并立刻弹出（已经晚了）。
- **要做的事**：像待办提醒一样**预先把通知排进系统**：
  - 工作段开始时 `zonedSchedule` 一条「该休息了」，时间 = 工作段结束时刻
  - 暂停 / 跳过休息 / 提前结束时 `cancel` 掉它
  - 通知 id 用固定值（一次专注只有一条）
  - 后台补算到点后仍有可能重复弹一次，用「已经排过系统通知」的标记去重
- **为什么值得做**：专注计时最典型的用法就是**锁屏把手机扣在桌上**，
  而现在的提醒恰好在这种用法下失效。
- **代价**：小。`TaskReminder` 里已经有现成的插件、时区、精确闹钟权限与渠道。

### 21. P5：把「时间规划」的残留字段真正迁掉

  删字段会让后面所有字段的序号前移、读错老数据。留下的死字段：
  - `Task.timeNeeded(4)` / `isBreakable(8)` / `blockArrangements(14)`

  - `SubTask` 上的同类字段（3/4 位）
  - `optionsBox` 里的 `workTime` / `restTime` / `allowTime`
