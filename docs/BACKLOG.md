## 一、功能

### 1. 局域网面板美化 + 更像 PC 客户端

- **现状**：面板（`lib/mod/lan_panel.dart`）是能用的素净样式，功能上只支持
  看待办 / 打钩 / 删除 / 新建 / 导出 / 导入。
- **以后要做**：视觉重新设计；支持编辑描述、子待办、标签、优先级、地点；
  也许加个看板/日历视角。
- **为什么先不做**：功能先跑通更重要；面板是纯前端单文件，改样式随时能改，不欠技术债。
- **触发条件**：局域网同步实际用起来、觉得「能用但难看」的时候。

### 2. 附件也跟着同步

- **现状**：`DataBundle` 只同步待办与标签，**不同步附件文件**。电脑面板上看到的
  附件条目在手机上有，但文件本身不会传。
- **以后要做**：附件按内容 sha1 命名，用同一个 HTTP 服务提供下载/上传端点，
  PC 端按需懒下载（不一次性全拉）。
- **为什么先不做**：附件是大文件，传输/断点/清理策略要单独设计，
  先让「文字待办」同步站稳。
- **触发条件**：用户反馈「照片/文件只能在手机上看」的时候。

### 3. WebDAV 作为可选的跨网络同步

- **现状**：只做了局域网直连（必须同一 Wi-Fi）。
- **以后要做**：`WebDavTransport`，让用户填**自己的**坚果云应用密码，
  实现真正的「在外面也能同步」。
- **重要澄清**：用户填自己的账号密码是**完全合规**的标准 WebDAV 客户端做法；
  不行的只是把**开发者自己的**账号密钥内置进 APK 给所有人共用。
- **为什么先不做**：对师生推广来说「注册坚果云 + 生成应用密码」门槛太高，
  不适合做默认路径；但作为**可选高级功能**很有价值。
- **触发条件**：局域网同步满足不了「不在同一 Wi-Fi 也要同步」的需求时。
- **工程上很便宜**：数据层是传输无关的（`DataBundle` + `DataMerge`），
  加一个 transport 是加法，不是重写。

### 4. Windows 桌面客户端（形态 B）

- **现状**：只做了形态 A（手机当服务器 + 浏览器面板）。
- **以后要做**：`flutter build windows` 出真正的桌面端，手机⇄电脑 都是 App。
- **主要障碍（已实测）**：
  - `workmanager`（上游自定义 fork，只支持 Android/iOS）**11 处**
  - `flutter_local_notifications`（不支持 Windows）**18 处**
  - 好消息：上游已有 `PlatformFeatures` 抽象（11 处）、`Platform.is` 23 处，
    基础不是从零开始
  - 已确认支持 Windows 的：`flutter_secure_storage`、`path_provider`、
    `file_picker`、`share_plus`、`qr_flutter`、`hive`、`table_calendar`
- **为什么先不做**：工作量比形态 A 大一个量级，而形态 A 已经能解决「电脑上看待办」。
- **触发条件**：真的需要在电脑上离屏使用（比如桌面上常驻提醒）时。

### 5. 外观统一 + 壁纸 / 色系

- **现状**：闹钟页有四套配色（`lib/design/alarm_theme.dart`，天依蓝/爱莉粉/清新绿/
  静谧紫），其它页面各写各的颜色。
- **以后要做**：抽一层统一 AppTheme；壁纸；色系跟随；闹钟配色与全局配色打通。
- **为什么先不做**：纯视觉，不影响功能；而且改起来会碰到大量上游文件
  （与我们「少碰上游文件」的接缝原则冲突），值得先把接缝压缩做完再动。
- **触发条件**：功能告一段落、想打磨观感的时候。

### 6. 排程算法改进（「接下来」页）

- **现状**：`arrange.dart` 用 `timeNeeded` 排班，但**界面里已经没有「预计耗时」
  输入了**（早前按需求删掉了时长选择器），所以现在等于拿默认值（1 小时）在排。
- **以后要做**：先把「预计耗时」输入找回来（胶囊式 15分/30分/1时/2时 比时间轮盘好用），
  再改排班算法。
- **为什么先不做**：算法再好，输入是错的也没意义。先补输入。
- **触发条件**：开始做排程功能时，**第一步就是补这个输入**。

### 7. AI 智能化的后续能力

- **现状**：正在做（见下一节）。
- **以后要做**：
  - AI 解析分享进来的消息 → 直接生成待办草稿（第一批）
  - AI 把一条待办拆成子待办（第一批）
  - **AI 识别分享进来的截图/图片**：现在的 `deepseek-flash`（V4.1 Flash）
    原生支持多模态，所以「把教务截图/群通知截图分享进来 → 自动变待办」
    技术上已经可行，只是要先把图片编码成 base64 走 messages 里的 image 内容块
  - 之后可以考虑：自然语言改期（「这周四之前」）、每周回顾摘要、按描述自动打标签
- **模型名会变**：DeepSeek 的模型名随发布变动（`deepseek-chat` → `deepseek-flash`
  就是这么变的）。`AiConfig` 里有一张过时名字的迁移表，官方再改名时更新那张表即可。
- **触发条件**：第一批跑顺、并且用户真的在用。

### 8. 手机端「局域网同步」的快速入口

- **现状**：入口在 设置 → 数据 → 局域网同步（三层）。
- **以后要做**：待办页右上角 ⋯ 菜单里加一个快捷入口 / 状态指示。
- **为什么先不做**：设置页里能找到，不急；且待办页是在持续跟上游改的文件，
  加东西要谨慎（接缝原则）。
- **触发条件**：发现自己每天都得点三层进去的时候。

### 9. 备份文件的自动清理

- **现状**：每次导出/导入都会往 `文档/celechron_backup/` 里写文件
  （`before-import.json` 每次覆盖，导出文件是新的时间戳文件），**不会自动清理**。
- **以后要做**：限制保留份数（比如最近 10 份），旧的自动删。
- **为什么先不做**：文件很小（几十 KB），短期内不会占满。
- **触发条件**：备份目录超过 20 份或用户反馈占空间时。

## 二、工程 / 接缝

### 10. 两处「整页重写」的搬迁（观察项）

- **现状**：`lib/page/task/task_view.dart`（417 行）与
  `lib/page/task/task_edit_page.dart`（1205 行）是整页重写的，改动量最大。
- **要不要搬到 `lib/mod/`**：**先不搬**。理由：它们**至今零冲突**
  （1.3 没动这两个文件），而搬出去会让上游对这两页的修复不再自动合并进来。
- **触发条件**：**上游改了这两个文件、并且产生冲突时**，再评估搬迁。
  平时每次跟版留意一眼即可。

### 11. CI 的取舍（可选）

  （只对 error 敏感 + 跑 132 个测试）。
- **可选做法**：如果在意私有仓库的 Actions 配额（免费 2000 分钟/月），
  可以整个删掉 `.github/workflows/`。
- **触发条件**：收到配额告警，或者觉得每次推送都跑 CI 没必要。

### 12. ~~标签库曾被清空的历史问题~~（已查明并修复）

> **已结案**：根因不是"被清空"，而是**标签库从来没有被这些来源写入过**——
> 只有「标签管理页编辑」「选择器里新建标签」「导入数据」三条路径会写库，
> 而 **AI 生成待办时直接给任务设标签**、局域网同步合并、以及旧数据里的标签
> 都只存在于待办身上。表现就是：筛选器看得到（它取的是「标签库 ∪ 待办标签」），
> 标签管理页和标签选择器却是空的（它们只读标签库）。
>
> 修复：`lib/mod/tag_harvest.dart` 做标签库自愈——TaskController 初始化时
> 把待办（含子待办）身上的标签补进库；AI 应用草稿时也会记住用过的标签。
> 这样 AI 复用已有标签的提示词也才真正有料可用。

- **现状**：早期发生过两次标签库被清空，当时的处置是加防护
  （`setTagLibrary` 拒绝空写入、标签管理页保存时与加载值做比较）并恢复了数据。
  **根因没有查明**，之后也没再复现。
- **以后要做**：如果再复现，抓 logcat + Hive 状态查一次。
- **为什么先不做**：无复现路径，盲改反而有风险。
- **触发条件**：**再次复现时**。
